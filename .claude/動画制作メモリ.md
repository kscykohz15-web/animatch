無職転生の解説動画をつくる仕組みで決めたことの全部。
**ルールが変わったら、その場でこのファイルを直す。** 決めたのに残していないと、
次のセッションで同じ議論をやり直すことになる。

最終更新: 2026-10-03（章タイトルのカード・パック版 v116）

## 0.5 毎回やること（言われなくてもやる）

**このチャンネルの仕事で何か作ったら、必ず `python 仕上げ.py` を通してから掲示板に出す。**
落ちたら board.html は作られない。通らないものは出さない。

```
python 仕上げ.py            確かめて、通ったら board.html まで作る
python 仕上げ.py --shirabe  確かめるだけ
```

見ているのは5つ。どれも「前に一度やらかしたこと」がそのまま検査になっている。

| | 見るもの | これが落ちた時に起きたこと |
|---|---|---|
| ① | 字幕用と読み上げ用で段落数・文の数が同じか | 音と字幕がずれる |
| ② | 8分以上あるか（6.46字/秒） | ミッドロール広告が付かない |
| ③ | 章のキーワードが本当に字幕に当たるか | 右上の章が出ない |
| ④ | タグの綴り・話数フォルダ・死んだキーワード | 絵が中身と合わない |
| ⑤ | 共通の設定が**ZIPを作る2か所とも**に入るか | そのパックに設定が入らない |
| ⑥ | **本体を小さな材料で本当に最後まで走らせる** | 動画が1本も作れない |
| ⑦ | 大文字の定数を2回定義していないか | あとの定義が前を黙って上書きする |
| ⑧ | パック版を上げ忘れていないか | 本人が古いパックを使い続ける |
| ⑨ | 演出が本人の編集のクセに合っているか | 自分のチャンネルらしく見えない |
| ⑩ | 字幕が言葉の途中で折り返していないか | 「直\|接」のように熟語が割れる |
| ⑪ | menu.ps1 が壊れていないか | パックが起動しない |
| ⑫ | 台本に BOM が付いていないか | VOICEPEAK 側が cp932 で落ちる |
| ⑬ | 章タイトルのカードが右半分に収まるか | 長い章の名前が絵の側まではみ出す |

⑤には**「演出.txt が名前を出している音が、全部パックに入っているか」**も入れた。
`ドーン.mp3` を足したとき、掲示板に入れ忘れて「音が鳴らない」になりかけている。

**⑤は「1か所でも呼んでいればよい」にしてはいけない。**
ZIPを作るところは2か所あり、片方だけ直す事故を3回やっている
（`miru_kekka.py` / `効果音` フォルダ / 共通設定ぜんぶ）。
数を数えて、2未満なら落とすこと。

### カタカナ語の途中では、そもそも切らない（2026-10-02）

字幕を大きくしたら（90→98px）、行が短くなって「ルー|デウス」が出た。
重みを上げるだけでは足りない。**切れる場所がそこしか無いと、重みは無意味。**
`_ok_break` で **カタカナ＋カタカナを禁止**し、収まらなければ文字を小さくする。

### 演出.txt に無い区切りは、間引きの前に落とす（2026-10-02）

「、」の演出をやめたら、演出が 14秒に1回 → **21.9秒に1回**に減ってしまった。
`kimeru_basho` が「、」の場所を残したまま全体の間引きに渡すので、
**何も出ない場所が「前回の時刻」を進めてしまい**、出したい「。」まで消えていた。
`en["kubun"]` に無い種類は、間引きの前に落とす。

### 字幕の折り返しは「熟語を割らない」（2026-09-30）

本人の指摘：「それぞれを直 / 接どうこうすることはできない。」
**`_TRANS` の重みが逆だった。** 漢字＋漢字(0.60)を、ひらがな＋ひらがな(1.00)より
安いコストにしていたので、熟語の真ん中で切るほうが「得」になっていた。

    漢字＋漢字   0.60 → 1.80   直|接 / 年|表 / 処|刑 / 第二十一|話
    カタカナ途中 0.95 → 2.00   カタカナ語の真ん中

全台本2051枚で、言葉の途中で切ったものが **15枚 → 0枚**。
`折り返し検査.py` が数えるので、重みをいじったら必ず回すこと。
「・」「…」のあとは切ってよい場所なので数えない。

### BGMは一定の音量（本人の指定・2026-09-30）

**`BGM控えめ` は `いいえ`。** 声のあるところだけ小さくする(ダッキング)のは
本人の好みではない。最初から最後まで同じ音量で流す。
仕組みは残してあるので、`はい` にすれば実測0.31倍まで下がる。

### 同じ絵は3回まで（本人の指定・2026-09-30）

「動画全体で同じ画像を使っている場合が多い。同じ風景ばかり流れると分かりにくい」

`見た目.txt` の **`同じ絵の上限` = 3**。選ぶときに3段構え：
① 最近つかっておらず上限未満 → ② 上限未満 → ③ ぜんぶ上限ならいちばん使っていないもの。
**③に落ちた枚数は画面に出す。**「候補が足りず N枚は上限を超えました」

検算：絵200枚/60枚/40枚で上限3回を1度も超えない。
絵30枚×3回 < 字幕120枚 のように**どうやっても足りないときだけ**超え、
そのときも1枚に偏らず4回ずつに散る。
**手で選んだ絵（ファイル名直書き）は上限の対象外**（5か所目の例外）。

### 速くする（2026-10-01・実測）

本人「音声と動画で1時間近くかかる」。**推測せず測った**（`scratchpad/bench/`）。
4コア・1920x1080・255枚・523秒に伸ばした数字：

| 工程 | 前 | 後 | やったこと |
|---|---|---|---|
| 断片を作る | 10.4分 | **5.3分** | 6本ずつ並べる＋ultrafast |
| つなぐ | 0.7分 | 0.7分 | ー |
| 書き出し | 7.3分 | **5.0分** | medium → faster |
| 確認用 | 7.8分 | **0分** | 既定でやめた |
| **合計** | **26.2分** | **11分** | **2.4倍** |

**いちばん効いたのは「やらなくていいことをやめる」。**
`miru_kekka.py`（採点）は **mp4 を1本も見ていない**。見るのは `一覧.txt` だけ。
255本の短い動画は採点に要らなかった。`--cuts` を付けたときだけ作る。
一覧.txt は必ず書く（ほぼ一瞬）ので、採点はいつでもできる。

**並列は思ったほど効かない。** ffmpeg 自体がスレッドを使うため。
実測：4コアで 2本同時=1.09倍 / 4本=1.57倍 / **6本=1.96倍**。
コア数ちょうどではなく、**×1.5 くらい走らせたほうが速い**。

**プリセットは断片では効かない。** veryfast 39秒 → ultrafast 35秒（1割）。
断片のコストは x264 ではなく、ffmpeg の起動と絵の読み込み。
書き出しでは効く（medium 27秒 → faster 19秒 → veryfast 13秒）。
スライドショーは動きが無いので faster で見た目は変わらない。
`見た目.txt` の `書き出しの速さ` で変えられる。

### 外部コマンドをパイプに通さない（2026-10-01）

`| Out-Host` を付けたら、**音声を作っている間ずっと画面が真っ白**になった。

Python は標準出力がコンソールなら行ごとに吐くが、**パイプだとためこむ**
（ブロックバッファ）。10分以上なにも出ず、止まったように見える。
前の回でエラーが見えたのは、落ちた拍子にためこみが吐き出されただけ。

**外部コマンド（python / ffmpeg）は、そのまま呼ぶ。パイプに通さない。**
`$env:PYTHONUNBUFFERED = '1'` も立てておく（保険）。

ではなぜ Out-Host を付けたのかというと、**PowerShell の関数の中では
外部コマンドの出力が「戻り値」に混ざる**ため。`if (MakeVoice)` が
失敗していても真になる。これは別のやり方で解く：

    function MakeVoice {
      $script:voiceOK = $false
      ...
      python $vp '台本_読み上げ用.txt'     # パイプに通さない
      ...
      $script:voiceOK = $true
    }
    MakeVoice
    if (-not $script:voiceOK) { ... }

**戻り値を使わず、`$script:` の旗で結果を伝える。** これなら両立する。
`ps1検査.py` が「外部コマンドをパイプに通していないか」を見る。

### 演出の密度は「演出の間隔」で決める

**種類ごとの `間隔` だけでは効かない。** 「。」と「、」が別々に数えるので、
合わせると倍の密度になる。実際 `間隔 4.0` ずつにしても 3.1秒に1回だった。
`演出の間隔`（全体、秒）で最後にもう一度間引く。章は必ず残す。

    0秒 … 174か所 /  3.1秒に1回   ← 多すぎ
   15秒 …  39か所 / 14.0秒に1回   ← いま
   25秒 …  26か所 / 20.8秒に1回   ← ほぼ章だけ

**数字を合わせる前に、まず「何秒に1回になるか」を出すこと。**
割合(%)だけ見ていると、密度が見えない。

### 演出は本人の動画の実測に合わせてある（2026-09-30）

本人の動画5本・127分を `mane.py` で測った数字に、`演出.txt` を合わせた。
**勘で決めない。`演出あわせ.py` で計算して合わせる。**

| | 設定 | 本人の実測 |
|---|---|---|
| パッと切る(2コマ以内) | 66% | 62% |
| はっきり溶かす(5コマ以上) | 34% | 37% |
| 一瞬暗くなる | 29% | 27% |
| 効果音が鳴る | 66% | 65% |
| 効果音のずれ | +0.09秒 | +0.093秒 |

決まった設定：**。=暗転 0.17秒 / 、=はさみ 0.07秒 / 章=ページめくり 0.40秒、
間隔は 。も、も 4.0秒、効果音のずれ +0.09秒。**

- **毎回の切り替わりでは鳴らさない。** 本人は65%。`間隔` で間引く。
- **いちばん多いのは2コマ（0.07秒）＝ほぼパッと切る。** 前の 0.16秒 は長すぎた。
- **効果音は切り替わりの少しあとに鳴る。** ぴったりではない。`効果音のずれ`。

`演出あわせ.py` は動画を作らずに計算するので、何度でも試せる。
`mane.py` と同じものさしなので、そのまま比べられる。

## 2. 台本のルール

- **読み上げ速度は 6.46字/秒（実測）。** 5.5字/秒だと思っていたのは誤り。
  2458字 → 6分20秒 で測った。見積もりはこの数字を使う。
- **8分以上にする。** YouTubeのミッドロール（途中広告）は8分以上の動画だけ。

- **口調は「第6回 ヒトガミの正体」が見本。** 本人が書いた原稿に合わせた形。
  ・冒頭は事実の言い切り。「老デウスの歩んできた人生が、壮絶すぎた。」
  ・次に「どうもこんにちは、かさです。」（あいさつは読み辞書で変換しない）
  ・「ということで今回の動画は、〜について考察していきたいと思います。」
  ・一人称で考えながら話す。「〜というわけです」「〜なんだとか」「〜かと思います」
  ・読者の疑問を先回りして口語で置く。「なら先に殺せばいいやん、となる方も」
  ・章の予告は「そして二つ目の助言は」「と、〜のことはここまでとして。」で自然にやる

- 組み立て：
  1. 挨拶（「無職転生、〜」）＋ **最初の80字にその回いちばん強い事実**
     （挨拶だけだと掴みが目次になる。事実を同居させる）
  2. 今回話す内容の概要
  3. どう進めるかの予告（章立て）
  4. ネタバレの断り
  5. **「それでは早速みていきます」** で本編へ
  6. 章ごとに「次は〜の話です」と予告
- 導入は180字（30秒）まで。中盤に引き留めを1つ。固有名詞は20種類以上。
- `kaku.py --check` で健康診断。`kaku.py --yomi` でカタカナ変換（実測93.8%）。
- 「第N話」→「第Nワ」は**正しい**（だいじゅういちわ と読ませるため）。
  「では」はそのまま（VOICEPEAKが正しく読む）。直すのは `読み辞書.txt`。

## 3. 字幕の切り方（何度も変えたので、順位ごと覚える）

**いまの既定は「「、」ごとに切る」（元の動き）に戻してある。**
本人から「字幕と音声がずれた」と言われて戻した。ただし下の検算のとおり、
**分割の設定で字幕がずれることはない。** 戻したのは指示だから。
細かくしたいときは `--kuten-moji 20 --kuten-tsunagi 5 --kuten-min 1.5`。

**優先順位：「。」で切る ＞ 短すぎない ＞ 長すぎない**
上から譲らない。これを決めていないと、条件が増えるたびに壊れる。

1. `。` `！` `？` は**必ず**切る。**ここは絶対。またいで結合しない。**
2. `、` は合計 **20文字**を超えないように切る（`--kuten-moji 20`）
3. **5文字以下、または1.5秒未満**は**後ろ**にくっつける
   （`--kuten-tsunagi 5` / `--kuten-min 1.5`）。「前」ではない（語順が変わる）
4. `、` が1つも無くて長い文は**切らない**。切る場所が無いので、しょうがない。
5. ②と③がぶつかったら③を上にする。結果20字超過が2割ほど出るが、承知の上。

3380字の台本で **209か所・1枚2.5秒**。数字を変えたときの目安：
18字/1.1秒→225枚、20字/1.5秒→209枚、24字/1.5秒→197枚。

### 手で選んだ絵は、機械の判定より上（4か所そろえる）

① 対象話数の外でも使う ② `使用不可` でも使う ③ 人ちがいの選び直しをしない

## 14. 演出（切り替え効果と効果音）

`演出.txt` で設定する。**台本も音声も作り直さずに、演出だけ変えられる。**

    効果音	なし      ← なし / シュッ / ポン / カッ / 自分の.wav

### 尺を1フレームも狂わせない作り（ここが肝心）

`xfade` は**使わない。** 重ねたぶん全体が縮み、音とずれるため。
209か所×0.3秒なら62秒も短くなってしまう。

代わりに、**断片の頭に前の絵を重ねて、それを透明にしていく。**

    [1:v]format=yuva420p,fade=t=out:st=0:d=D:alpha=1[f];
    [0:v][f]overlay,format=yuv420p[v]

断片の長さは `-frames:v N` のままなので、**フレーム数が変わらない。**
実測：演出なし360フレーム/12.00秒 → 演出あり360フレーム/12.00秒。同じ。

効果音も同じ考え方。`adelay` を何百個も並べるとグラフが大きすぎるので、
**無音のバイト列に貼りつけて1本のwavを作る**（209か所で0.67秒）。
混ぜるときは `amix=inputs=2:duration=first:normalize=0`。
**normalize=0 を忘れると声の音量が下がる。** duration=first で長さは声のまま。
実測：声も混ぜたあとも 23,064,300サンプルで同じ。

### 区切りの種類ごとに、音とエフェクトを変える（本人の指定）

    区切り	、	はさみ.mp3	はさみ	0.16
    区切り	章	カードをめくる.mp3	ページめくり	0.40

種類は強い順に 章 ＞ 。 ＞ 、。前のセリフが「。」で終わっていれば「。」扱い。
**効果音3つは本人からもらった実物**（`効果音/` に同梱済み）。

**音は「立ち上がり」を切り替わりに合わせる。** ファイルの頭ではない。
カメラは0.05秒、はさみは0.05秒、カードは0.10〜0.25秒あとに鳴るので、
そのぶん前に置かないと、音が遅れて聞こえる。`se_wav_ready` が自動で測る。

### BGM（2026-09-29 追加）

**採用した曲だけ掲示板に埋め込む。** `build.py` が
`scratchpad/video/BGM/*` を base64 で `<script data-bgm>` にする。
ふおんなきり.mp3（1.16MB）を入れて掲示板は 2.28MB → 3.70MB。
**候補を全部は入れられない**（20本なら32MBで、上限16MBを超える）。
候補は数字で測って（長さ・LUFS・前後の無音・いちばん静かな所）本人に選んでもらい、
選ばれたものだけ入れる。作業フォルダ側の `BGM` フォルダは `Prepare` が必ず作る。

`演出.txt` のいちばん下：

```
BGM	ふおんなきり.mp3
BGMの音量	0.10
BGMのフェード	3
BGM控えめ	はい
```

- **足りなければくり返す。長ければ切る（`-t`）。**
  くり返しは `-stream_loop` だけでは**だめ**。実際の曲（ふおんなきり.mp3）で、
  頭に0.5秒・終わりに2秒の無音があり、1周ごとに**-44dB の穴**があいた。
  二段構えにすること：
  1. `bgm_mugon_kezuru` … 20msごとの山の高さを見て、いちばん大きい所の
     2%未満を無音とみなして前後を削る。両端に15msのフェード（プツッ消し）。
  2. `bgm_tsunagu` … 終わりの2秒と次の頭の2秒を、四分の一円の形で
     重ねて入れかえる（等パワーのクロスフェード）。
     23,064,300サンプルを触るので **`array('h')` を使う**。
     ふつうの list だと int が1個28バイトで 600MB を超える。
  結果、つなぎ目は -19.1dB（前後 -14.8 / -17.5）。穴がなくなった。
- **頭と終わりは afade。** 終わりは「動画と声の短い方」に合わせて終わる。
- **BGM控えめ＝ダッキング**（`sidechaincompress`、声を鍵にする）。
  実測で **0.35倍**まで下がる。使えない ffmpeg では自動であきらめて、
  音量そのままで入れる（ずれなどの害は出ない）。
- **`sidechaincompress` は終わりを 0.48秒ほど削る。**
  `apad` と `-t` で元の長さに戻すこと。戻さないと BGM だけ早く終わる。
  長さの確認は **ffprobe ではなく `wave` モジュールで数える**
  （同梱の ffprobe は当てにならず、11.52秒と嘘をついた）。

**検算（毎回これを通す）**
1. 長さが動画ちょうど（529200サンプル＝12.000000秒）
2. 5秒の曲が12秒までくり返されている
3. 頭0.3秒と終わり0.3秒が、まんなかの 0.06倍
4. ダッキングで短くならない
5. **声＋効果音＋BGM を混ぜたものから、効果音とBGMを引くと、声と完全に一致（差 0）**

`amix` は **`normalize=0`** と **`duration=first`**。本数が増えても同じ。

### 同梱リストは2つある（またやった）

`効果音` フォルダは ZIP には入っていたのに、**`Prepare` が作業フォルダに
コピーしていなかった。** `miru_kekka.py` と同じ穴。

### 検算の道具（scratchpad/video/、パックには入れない）

| 道具 | すること |
|---|---|
| `shou_check.py` | 章のキーワードが本番と同じ切り方で当たるか。順番・近すぎも見る |
| `全部しらべる.py` | 8本ぶんまとめて |
| `plan_check.py` | タグの綴り・話数フォルダ・死んだキーワード・当たる割合 |
| `当て方.txt` | 言葉 → 絵 の対応表。ここを厚くすると次の台本にも効く |
| `プラン下書き.py` | 台本＋画面表示＋当て方 → 画像プランの下書き |
| `プラン全部作る.py` | 7本ぶん。**章ごとの @@話数 はここに書いてある** |

**`@@話数` は何度でも書ける（書いた所から下に効く）。**
話が全編に渡る台本（人生年表・伏線7選など）は、章ごとに切り替えること。
1つに固定すると、別の期の絵を拾ってくる。

台本を直したら **`python プラン全部作る.py` を回しなおす。** 全部作り直して検算まで出る。

現状：章は8本とも全部当たる。絵は当て方が効くのが52〜69%、
残りもその章の話数の中から拾うので、話数ちがいにはならない。

# 動画制作メモリ ─ かさ【ゆるオタ】チャンネル

無職転生の解説動画をつくる仕組みで決めたことの全部。
**ルールが変わったら、その場でこのファイルを直す。** 決めたのに残していないと、
次のセッションで同じ議論をやり直すことになる。

最終更新: 2026-09-27 / パック v87

## 1. 渡し方

- 掲示板: <https://claude.ai/artifact/BHk8FgTw6nibMh9BnREfjP>
- `scratchpad/` で作って `build.py` で `board.src.html` → `board.html` に流し込む。
- Python は `sync_py.py` で `<script id="py-*">` に同期する。
  **手で貼らない。** 貼り忘れると、直したのにパックに入らない。
- 出すたびに `PACK_VERSION` を上げる。上げないと本人が古いパックを使い続ける。
- パックの中身を増やしたら **2か所**に足す。片方だけだと黙って消える。
  ① ZIPに入れる一覧（`pys` 配列）② 作業フォルダへコピーする一覧（`Prepare`）

## 2. 台本のルール

- **読み上げ速度は 6.46字/秒（実測）。** 5.5字/秒だと思っていたのは誤り。
  2458字 → 6分20秒 で測った。見積もりはこの数字を使う。
- **8分以上にする。** YouTubeのミッドロール（途中広告）は8分以上の動画だけ。
  かつては10分だったが2020年に8分へ短縮された。ねらいは8分30秒〜8分50秒。
- 組み立て：
  1. 挨拶（「無職転生、〜」）＋ **最初の80字にその回いちばん強い事実**
     （挨拶だけだと掴みが目次になる。事実を同居させる）
  2. 今回話す内容の概要
  3. どう進めるかの予告（章立て）
  4. ネタバレの断り
  5. **「それでは早速みていきます」** で本編へ
  6. 章ごとに「次は〜の話です」と予告
- 導入は180字（30秒）まで。中盤に引き留めを1つ。固有名詞は20種類以上。
- `kaku.py --check` で健康診断。`kaku.py --yomi` でカタカナ変換（実測93.8%）。
- 「第N話」→「第Nワ」は**正しい**（だいじゅういちわ と読ませるため）。
  「では」はそのまま（VOICEPEAKが正しく読む）。直すのは `読み辞書.txt`。

## 3. 字幕の切り方（何度も変えたので、順位ごと覚える）

**優先順位：「。」で切る ＞ 短すぎない ＞ 長すぎない**
上から譲らない。これを決めていないと、条件が増えるたびに壊れる。

1. `。` `！` `？` は**必ず**切る。**ここは絶対。またいで結合しない。**
2. `、` は合計 **20文字**を超えないように切る（`--kuten-moji 20`）
3. **5文字以下、または1.5秒未満**は**後ろ**にくっつける
   （`--kuten-tsunagi 5` / `--kuten-min 1.5`）。「前」ではない（語順が変わる）
4. `、` が1つも無くて長い文は**切らない**。切る場所が無いので、しょうがない。
5. ②と③がぶつかったら③を上にする。結果20字超過が2割ほど出るが、承知の上。

3380字の台本で **209か所・1枚2.5秒**。数字を変えたときの目安：
18字/1.1秒→225枚、20字/1.5秒→209枚、24字/1.5秒→197枚。

## 4. 画像を文章に合わせる

- **`画像カタログ.txt` には見た目のタグだけ入れる**（髪色・年齢・服・持ち物）。
  人物名は `人物ルール.txt` で**読み込むときに**決める。
  こうしておけば、ルールを1行直すだけで1万枚の判定がやり直せる。**再解析しない。**
- `@@話数` は `#指定` の探す範囲。**その中に無ければカンマの次の候補に譲る。**
  全部外れたときだけ他の話数へ広げる。これを忘れると黙って他の期から拾ってくる。
  （話数の種類が11 → 4 に減った。いちばん効いた直し）
- **当たった規則のうち「いちばん長いキー」を使う。** 先に書いた行ではない。
  短いキーが後ろの文まで拾う（「この時」が「この時点で…」を拾った）。
- 同じ絵は直前12か所に出たら避ける（`AVOID_WINDOW`）。
- 同じ文の続きでも絵は次へ進める。前と同じ番号にすると句読点で割った意味が無い。
- セリフの人名と絵の人物が**別人**のときだけ選び直す。誰も写っていない絵はそのまま。
  選び直しは**必ず対象話数の中から**探す。
- **老デウスは年をとったルーデウス本人。** どちらの絵でも間違いではない。

### 手で選んだ絵は、機械の判定より上（4か所そろえる）

画像プランに**ファイル名を直接**書いた絵は、
① 対象話数の外でも使う ② `使用不可` でも使う ③ 人ちがいの選び直しをしない
④ 採点でも責めない。
**4つ全部そろえないと本人の指定が黙って消える。**
実際、10枚もらって4枚消えた（1枚は使用不可で除外、1枚は人ちがいで差し替え、
2枚は規則の順番負け）。プラン冒頭に「手で選んだ絵」の枠を置く。
2回目以降は自動に回したいので、うしろに `#指定` を並べる。

## 5. 見ずに直す仕組み（採点）

動画はこちらから見られない。だから突き合わせる。

1. `はじめる.bat` → `2` → 「**2 動画 + 1枚ずつの確認用**」
2. `確認用/一覧.txt`（何秒・どの絵・何をしゃべったか）と `採点.txt` が自動でできる
3. 本人が `採点.txt` を貼る → こちらが直す場所を名指しできる
4. `shiken.py` で**動画を作り直さずに**割り当てだけ試す（10分 → 5秒）

`miru_kekka.py` が見るのは5つ：人ちがい / 話数ちがい / 情景ちがい / 使いすぎ / 使用不可。

**点数を信じすぎない。** 言葉の突き合わせなので、合っているのに「ちがう」と出る。
点数は並べるための道具。「絵で表せる言葉が無い」は台本の都合で、失敗ではない。

## 6. 音・字幕・絵をそろえる

- 時刻表は **① `subtitle.srt` の本文が台本と完全一致するときだけ使う（strict）**
  → ② 音声の長さだけで組む → ③ やむを得ず文字数で振り分け（大きな警告つき）。
  **②③を①より先に置くと必ずずれる。** これが同期ずれの原因だった。
- `LEAD = 0.12秒`（絵を少し先に出す）。ずれの実測は0.119秒＝この値どおり。
- **台本と音声のずれは、日付ではなく中身で判定する。**
  パックを入れ直すと台本の更新日時だけ新しくなるので、日付で見ると毎回誤警告になる。
  `1` で音声を作ったとき `音声のもと.txt` に台本を控え、ハッシュで比べる。

## 7. つまずいた所（同じ穴に落ちないため）

- 同梱の `ffprobe` は**尺しか返さないPythonの偽物**。ストリーム情報は
  `ffmpeg -i f 2>&1 | grep "Stream #"` で見る。2回だまされた。
- PowerShell の `Tee-Object` は**日本語を壊す**（UTF-16LE）。ログはPythonに書かせる。
- cp932 は `═` を出せない。**ファイルを書いてから画面に出す。**
  逃げ道の `.decode("ascii")` も失敗するので、画面の文字コードに合わせて置きかえる。
- `write_cuts` は `-c copy` だとキーフレームに吸われて番号がずれる。**再エンコードする。**
- VLMの**空の返事を失敗として数える**。数えないと8716枚が無言で失敗して8時間無駄になる。
- JSONスキーマの配列は `token repeat limit` を起こす。**素のenum文字列**にする。
- 書式の格下げ（スキーマ→json→なし）は**成功したら必ず戻す**。戻さないと数枚で全体が腐る。
- `使用不可` は自動選択からだけ外す（手で選んだ絵は残す）。839枚該当した。

# ゆるオタの部屋 ブログ自動運用 設計書

作成日: 2026-11-18
対象サイト: https://kasa-yuruotablog.com/ （WordPress / AFFINGER）
関連チャンネル: https://www.youtube.com/@kasa-yuruota （かさ【ゆるオタ】）

## 1. 目的

ブログ運用を運営者の手から離す。記事の企画・執筆・裏取り・投稿を Claude が担い、
運営者は本文を読んで可否を返すだけにする。

達成したいこと（運営者の指定、優先度順）:

1. 検索流入を増やし、広告・アフィリエイトで収益を上げる
2. 記事数を積み上げてサイトを資産化する
3. 趣味の発信として読み物の面白さを保つ

ブログのカテゴリ構成は動画のテーマに対応しており（「学園ラブコメ・恋愛もの」「バトルアクション」
「Youtube動画」が記事0件）、運営者が同じ構想を持ちながら未完に終わったことを示している。

## 3. 方針

**ブログを YouTube チャンネルのテキスト版として位置づける。**

ネタの第一ソースは自分の動画。再生数が需要の証拠になるため、キーワードを推測する必要がない。
Web 検索はネタ探しではなく、配信先の裏取りと新作キーワードの補完に使う。
動画に紐づかない単独テーマも混ぜてよい（運営者の指定）。

相互強化:

- 動画 → ブログ: 概要欄の記事リンクが、検索順位が育つ前の初期流入を供給する
- ブログ → 動画: 記事内の動画埋め込みが滞在時間を伸ばし、再生数も増やす

## 4. 運用フロー

```
[日次トリガー] → Claude 起動
      ↓
  RUNBOOK.md を読む（記憶に依存しない）
      ↓
  topics.yaml から status=backlog の最優先エントリを取得
      ↓
  執筆（style.md の規約に従う）＋ Web 検索で裏取り
      ↓
  品質ゲート（自己検査）── 不合格なら破棄して次のネタへ
      ↓
  WordPress に status=draft で投稿
      ↓
  レビューページ（固定URL）を更新 → 運営者に提示
      ↓
[運営者] 読んで「OK」または「ボツ（理由）」を返信
      ↓
  OK → status=publish に更新 / ボツ → ゴミ箱へ、理由を ledger.json に記録
      ↓
  posts/ に本文を保存、topics.yaml と ledger.json を更新して git push
```

レビューページの URL は固定し、毎回同じ場所を更新する。
運営者はブックマーク1個を開けばその日の下書きが並んでいる状態にする。

下書きを先に WordPress へ入れることで、公開操作はステータス変更のみになり、
レビューした本文と公開される本文が食い違う余地がなくなる。

## 5. ファイル構成

リポジトリ `kscykohz15-web/animatch` の `blog/` 配下に閉じる。
animatch 本体のコードには一切触れない。

```
blog/
  RUNBOOK.md        起動時に最初に読む手順書
  style.md          文体・構成・禁止事項の規約
  topics.yaml       ネタ帳（バックログ）
  ledger.json       公開済み・却下済みの台帳
  posts/            生成した本文（Markdown + frontmatter）
  scripts/wp.mjs    WordPress REST クライアント
```

`RUNBOOK.md` が設計の要。会話の要約で記憶が失われても、セッションが切れても、
これを読めば同じ品質で続行できる。長期運用を成立させるのは記憶ではなくこのファイル。

### topics.yaml のエントリ

```yaml
- id: t0001
  title_draft: "記憶を消してもう一度見たいアニメ20選"
  keyword: "記憶を消して もう一度見たい アニメ"
  source: youtube            # youtube | search
  video_id: kqrlGOhoBI8      # source=youtube のとき
  video_views: 314000
  template: list             # list | vod_guide | similar | review | news
  category: おすすめアニメ
  priority: 1
  status: backlog            # backlog | drafted | published | rejected
  added: 2026-11-18
```

## 6. 記事の型

既存記事から抽出した構成をそのまま踏襲する。

### list（まとめ記事・動画連動）

```
導入（フックと動画への言及）
[動画埋め込み]
H2 <テーマ>アニメ<N>選
   H3 作品名 ×N（各: 基本情報 / あらすじ / 推しポイント / 配信先）
H2 おすすめの動画配信サービス（比較表＋アフィリエイト枠）
```

### vod_guide（作品単体）

```
導入1文
H2 「作品名」が見れる動画配信サービス(アプリ・サブスク)まとめ
   H3 現在配信されているサービス一覧
   H3 配信が確認できなかったサービス一覧
H2 作品情報とあらすじ
   H3 作品情報 / H3 あらすじ
H2 見どころと個人的おすすめポイント
   H3 ×2
H2 「作品名」と似ている作品
   H3 ジャンル別
H2 アニメ見放題におすすめのサブスク
```

その他の型: `similar`（類似作品レコメンド）、`review`（レビュー・考察）、`news`（放送情報）。

## 7. 品質ゲート

運営者に提示する前に Claude 自身が検査する。不合格の記事は提示しない。

- **事実**: 放送年・話数・配信先・声優・原作などの固有名詞は、検索で裏が取れたものだけ記載する。
  取れなければ曖昧表現で逃げずに削除する
- **出典**: 記事末尾に参照元リンクを残す
- **重複**: ledger.json と既存記事タイトルに照合し、既出テーマは書かない
- **鮮度**: 配信先には確認日を明記し、公式での確認を促す一文を入れる
- **禁止**: 未確認の数値、無警告のネタバレ、他サイトの文章の流用
- **SEO**: タイトルは32文字前後で主キーワードを前方に置く。スラッグは英数。meta description を設定
- **AdSense 規約**: 性的な内容を扱う動画（「放送ギリギリのHなアニメ」等）は記事化しない。
  サイト全体の広告停止リスクを避ける

## 8. 失敗時の扱い

黙って品質の低いものを出すより、空振りを報告する。

- **裏が取れずネタが成立しない** → そのネタを rejected にして次へ。全滅なら理由付きで報告
- **WordPress API 障害** → 指数バックオフで再試行。失敗しても本文は git に残して報告
- **ネットワーク遮断** → 報告のみ

## 9. 既知の障害（運営者の対応待ち）

### 9.1 全レスポンスへの AdSense タグ混入【重大・未解決】

すべての HTTP レスポンスの先頭に以下が出力されている。

```html
<head>
<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-..."
     crossorigin="anonymous"></script></head>
```

影響:

- **sitemap.xml が XML として致命的エラー** → Google がサイトマップを読めない
- **RSS フィードも同様に破損**
- **HTML が `<!DOCTYPE html>` より前に `<head>` を持つ** → ブラウザが互換モードで描画
- **REST API の JSON が破損** → ブロックエディタが動かない可能性

原因の推定: AdSense のコードを PHP ファイルの `<?php` の前か `?>` の後ろに直接貼った状態。
確認箇所は子テーマの functions.php、wp-config.php、コード挿入プラグインの設定欄。

**自動化側の回避策**: REST レスポンスの先頭から最初の `{` または `[` までを除去して解析する。
投稿自体は可能なため、この不具合は記事生成を止めない。ただし SEO 目標の土台が欠けたままになる。

### 9.2 `/wp-json/` パスの 403 遮断【対処済み】

サーバー側で `/wp-json/` が遮断されている。`?rest_route=` 形式は通るため、
クライアントはそちらを使う。セキュリティ設定として妥当なので修正不要。

### 9.3 収益リンクの大半が無報酬【重大・後回し】

全10記事の外部リンク監査結果:

| 種別 | 件数 | 報酬 |
|---|---|---|
| afb（t.afi-b.com）正規アフィリエイトリンク | 46 | 発生する |
| その他の VOD リンク | 約700 | **発生しない** |

無報酬側の多くは `yclid`（Yahoo広告）や `msclkid`（Microsoft広告）のクリックIDが付いた URL で、
検索結果の広告枠からコピーされたもの。運営者のアフィリエイトIDを含まない。

**運営者の判断により、既存記事の修正は後回しとし、新規記事の作成を優先する。**
ただし新規記事も同じ型を使う以上、正しいリンクの確定は早いほどよい。
afb の提携済み案件が判明するまで、新規記事では afb の既存リンクのみを使い、
提携が確認できないサービスには報酬の発生しないリンクを置かない。

### 9.4 YouTube 概要欄へのリンク追加

Claude は YouTube への投稿権限を持たない。記事公開後に概要欄へリンクを貼る作業は運営者が行う。
Claude は貼り付け用のテキストを用意して渡す。

## 10. 段取り

- **フェーズ1**: 基盤ファイル（RUNBOOK / style / topics / wp.mjs）を作成し、
  文体すり合わせ用の記事を数本生成してレビューに出す。本数は運営者が決める
- **フェーズ2**: WordPress への実投稿を通し、下書き投稿と公開 API の動作を確認する
- **フェーズ3**: 品質に納得が得られた時点で定期タスクを有効化する。
  日次「1本執筆してレビューに出す」＋ 週次「ネタ帳を補充する」

定期タスクはこの会話に向けて発火させる。別セッションで発火させると、
記事を作ったセッションと運営者が可否を返すセッションが食い違うため。

## 11. 却下した案

- **毎回その場で検索してテーマを決める**: 何を書いたか記憶できず、同一テーマの重複が起きる。
  会話の要約が走れば記憶は確実に失われる
- **テンプレート型の機械的量産のみ**: 全記事が同じ構成になり、
  目的3（趣味の発信としての面白さ）が失われる
- **専用のレビュー画面を別途構築**: WordPress の認証情報をそのページ側に渡す必要があり、
  設計と安全対策の工数に見合わない
- **期限付き自動公開**: 見落とした記事が公開されるリスクを運営者が負う
